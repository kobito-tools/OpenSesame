# アプリ間の約束（永久に変えないデータの形）

kobito シリーズのアプリどうしは、**お互いのコードを呼びません**。つながりはこの文書で決めたファイルとURLだけです。ここに書いた形は、アプリの種類が増えても、各アプリの中身が変わっても、変更しません。

> **v1 確定（2026-10-15）**：次の確認を経て、この形を確定しました。以後は「変更の規則」に従い、任意の項目・種類を足すことだけができます。
> - 検証用の試作（今は kobito-workspace から外し、kobito-tools の `_backup/spikes/` に保管）：iframe 埋め込みと ⑤、`.app` への ② の受け渡し、常駐プロセスからの小さなウインドウ（いずれも macOS）
> - Python のアプリ2つを共通部品の写しに載せ替え、kobito-workspace に埋め込んで、③ カード・④ 起動情報・⑤ 埋め込みメッセージ（`navigate` を含む）・⑥ 基準パスの履歴・⑦ 受け渡しの口が動くこと
> - Windows での動作は未確認です。Windows で問題が見つかっても、約束の形ではなく各アプリと共通部品の実装で対応します。

## 名指ししない規則

- どのアプリも（ハブの kobito-workspace も含めて）、コード・画面・README・設計書のどこでも、**ほかのアプリを名指ししない**。アプリの名前や ID の一覧も持たない。
  - ほかのアプリと何ができるかは、約束を通して実行時に知る。たとえば、受け渡し先の一覧は起動情報（④）から作る。
  - シリーズのアプリの紹介は、GitHub の organization `kobito-tools` のプロフィールに任せる（topic `kobito-app` の付いたリポジトリから一覧を作る）。各アプリの README は「kobito シリーズの1つ」と1行だけ書く。
- 例外は1つだけ。約束の URL の中の、自分以外のアプリID（`kobito://<アプリID>/…`）。これは実行時に起動情報（④）から得るか、利用者が選んだものを保存するだけで、コードに直接書かない。
- こうすることで、アプリを新しく作ったり、消したり、作り替えたりしても、ほかのアプリの文書や画面と食い違わない。
- この文書の例に出てくる `sample`・`other` は、説明のための架空のアプリです。

## 変更の規則（すべての約束に共通）

- 項目を**削除しない・名前を変えない・意味を変えない**。
- 足してよいのは**任意の項目だけ**。読む側は知らない項目を無視する。
- 読む側は、必須の項目が欠けている・形が違う1件だけを捨てて、残りを使う（1件の不備で全体を止めない）。
- 版番号 `v` は 1 のまま上げない。上げなければならない変更は、この約束の外で新しい仕組みとして作る。

| 番号 | 何を指すか | 形 | 置き場所 |
|---|---|---|---|
| ⓪-1 | データセット | `dataset.json`（既存） | `<基準パス>/.kobito-tools/dataset.json` |
| ⓪-2 | 共有タグ | `tags.json`（既存） | `<基準パス>/.kobito-tools/Tags/tags.json` |
| ① | ファイル | ファイル参照 | 参照する側のアプリのDBの中 |
| ② | 他アプリのデータ | リンク | 参照する側のアプリのDBの中 |
| ③ | 横断表示 | カード | `<基準パス>/.kobito-tools/<App>/cards.jsonl` |
| ④ | アプリの起動方法 | 起動情報 | PC固有領域の `kobito-tools/apps/<アプリID>.json` |
| ⑤ | workspace に埋め込まれたアプリとのやり取り | 埋め込みメッセージ | iframe と workspace の間の `postMessage` |
| ⑥ | このPCで使った基準パス | 基準パスの履歴 | PC固有領域の `kobito-tools/datasets.json` |
| ⑦ | アプリからアプリへ中身を渡す | 受け渡しファイル | OS の一時フォルダの `kobito-share/` |

⓪ は、シリーズの最初のアプリで運用していた形をそのまま引き継ぎます。

アプリの入口（`launch.py`）と目印（`kobito-app.json`）は、データの受け渡しではなく、アプリの配り方と見つけ方の決まりなので、この約束には入れず、[APP_PACKAGE.md](APP_PACKAGE.md) に別の決まりとして置きます（2026-10-21）。`launch.py --metadata` が出すのは ④ と同じ形の JSON で、④ の項目と意味はそのままです。

## アプリID

URL・カード・起動情報で使う、変えない名前です。**アプリIDの一覧は、どこにも置きません。** 各アプリが自分で名乗ります。

| 決まり | 内容 |
|---|---|
| 名乗る場所 | 目印 `kobito-app.json` の `app`（[APP_PACKAGE.md](APP_PACKAGE.md)）と、起動情報④の `app`。2つは同じにする |
| 使ってよい形 | 英小文字で始まり、英小文字・数字・`-` だけで、40文字まで（`^[a-z][a-z0-9-]{0,39}$`）。形の違う ID の目印・起動情報は、まるごと捨てる |
| 選び方 | アプリの名前を英小文字にしたものなど、ほかと重ならなそうな言葉にする。`workspace` はハブ（kobito-workspace）の ID なので、ほかのアプリは使わない |
| 変えない | 一度使い始めた ID は変えない。URL（②）・カード（③）・起動情報（④）・ランチャーが覚えた操作が、この ID でつながっているため |

### ID がかぶったとき

2つのアプリが同じ ID を名乗ると、起動情報（④）は ID ごとに1つのファイルなので、片方がもう片方を上書きしてしまいます。そこで、かぶりに気づいた側は、**どちらかを勝手に選ばず、知らせて止めます**。

| 場面 | 扱い |
|---|---|
| workspace が、アプリを探すフォルダから、同じ ID の目印を2つ以上見つけた | どれも登録させない（「登録する…」を出さない）。「見つかったアプリ」に、かぶっている ID と、もう片方のフォルダを出して知らせる |
| 見つけたアプリと同じ ID で、別の場所のアプリがすでに④に登録されている | 登録済みのアプリはそのまま使い、見つけたほうは登録させない。かぶっていることを知らせる |
| kobito-workspace の `scripts/check_contracts.py --find <フォルダ>` | 上の2つを見つけて一覧に出し、終了コード 1 で終わる |

直すのは、かぶったアプリの作者です。あとから作ったほうのアプリの ID を、使い始める前に変えます。

## ① ファイル参照

```json
{ "root": "base", "path": "論文/機械学習/x.pdf", "name": "x.pdf", "size": 1234567, "sha256": "…" }
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `root` | ○ | `"base"`＝基準パスからの相対パス（どのPCでも有効）／`"absolute"`＝絶対パス（そのPCでだけ有効） |
| `path` | ○ | `base` なら `/` 区切りの相対パス（`..` を含まない）、`absolute` ならOSの絶対パス |
| `name` | ○ | 保存した時点の表示名。ファイルが見つからなくても表示に使う |
| `size` | | バイト数。探し直しの絞り込みに使う |
| `sha256` | | 内容のハッシュ値。移動・改名されたファイルを探し直すときに使う |

- ファイルが見つからないとき、参照を持つアプリ自身が 共通部品（`kobito_kit`）で探し直します（名前と大きさで絞り、sha256 で確かめる）。見つかれば自分のDBの `path` を書き換えます。ほかのアプリには触れません。
- ファイルを開くときは OS の既定のアプリで開きます。

## ② リンク

```json
{ "url": "kobito://sample/open/memo-…?dataset=<データセットキー>", "title": "9月23日の会議メモ", "app": "sample" }
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `url` | ○ | `kobito://<アプリID>/<宛先が決める部分>`。`dataset` を付けると、宛先はその基準パスで開く |
| `title` | ○ | 保存した時点の表示名。宛先のアプリが無くても表示に使う |
| `app` | ○ | 宛先のアプリID |

- `<宛先が決める部分>` を読めるのは宛先のアプリだけです。参照する側は文字列のまま保存し、共通部品の `open_link()` に渡すだけにします。
- 宛先のアプリは、一度受け付けた URL の形を受け付け続けます（内部の作りを変えても、古い形を読み替える）。
- 宛先のアプリが無い・開けないときは、`title` を灰色で表示します。

## ③ カード

各アプリは、横断表示に出したいものを1行1件のJSON（JSON Lines）で書き出します。workspace はこれを読んで、HOME・横断検索・統合カレンダーを組み立てます。

```json
{"v":1,"app":"sample","id":"action-…","kind":"予定","title":"論文を読む","start":"2026-10-14T10:00:00+09:00","end":"2026-10-14T11:30:00+09:00","tags":["tag-…"],"text":"…","url":"kobito://sample/open/action-…","updated":"2026-10-14T09:12:00+09:00"}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `v` | ○ | `1` |
| `app` | ○ | 書き出したアプリのID |
| `id` | ○ | アプリの中で一意で、変わらない文字列 |
| `kind` | ○ | 表示用の種類名（「メモ」「予定」「Todo」「書籍」など）。読む側は意味を解釈しない |
| `title` | ○ | 見出し |
| `url` | ○ | ② の形の URL。カードを押すとこれを開く |
| `updated` | ○ | 最終更新日時（ISO 8601、時差付き） |
| `date` | | 日付だけを持つもの（`YYYY-MM-DD`）。カレンダーの終日欄に出る |
| `start`・`end` | | 時刻を持つもの（ISO 8601、時差付き）。`end` は省略できる |
| `due` | | 期限（`YYYY-MM-DD` または ISO 8601）。期限の近いものとして HOME に出る |
| `done` | | `true` なら完了済み |
| `tags` | | ⓪-2 のタグIDの配列 |
| `text` | | 検索用の本文の抜粋（2000文字まで） |

- 置き場所は `<基準パス>/.kobito-tools/<App>/cards.jsonl` です（`<App>` は ⓪-1 の各アプリのフォルダ）。
- 書くのはそのアプリだけです。変更があるたびに、一時ファイルに全件を書いてから置き換えます。
- 削除したものは、ファイルから行を消すだけにします。
- workspace は更新日時が変わったファイルだけを読み直します。workspace はカードを書き換えません。

## ④ 起動情報

`uv run` で起動するアプリは OS に URL スキームを登録できないため、各アプリは起動のたびに、自分を起動するためのコマンドをPC固有領域へ書き出します。

```json
{ "app": "sample", "name": "Sample", "command": ["/opt/homebrew/bin/uv", "run", "--project", "/Users/…/Sample", "/Users/…/Sample/launch.py"] }
```

Python のアプリの `command` は、リポジトリの直下の `launch.py` を指します（[APP_PACKAGE.md](APP_PACKAGE.md)。2026-10-21 からの決まり。`command` の意味は変わりません）。

| 項目 | 必須 | 内容 |
|---|---|---|
| `app` | ○ | アプリID |
| `name` | ○ | 表示名 |
| `command` | ○ | 起動コマンド（シェルを通さず実行する）。② の URL は最後の引数として足して渡す |
| `embed` | | workspace の中で表示するときに、`command` の後ろへ足す引数（例：`["--embedded"]`）。無ければ、そのアプリは workspace の中に表示しない |
| `receive` | | ⑦ の受け渡しを受け付ける口の配列（下の表） |
| `name_en`・`icon`・`color`・`kinds`・`actions` | | 見せ方と操作（下の「見せ方と操作」） |

- 置き場所は macOS で `~/Library/Application Support/kobito-tools/apps/`、Windows で `%APPDATA%\kobito-tools\apps\` です。
- すでに起動している場合、宛先のアプリは2回目の起動を受け取って、起動中のウインドウへ渡します（Python のアプリは、共通部品の `/control/…` で受け取る）。
- `.app` のアプリは、`command` に `["/usr/bin/open", "-b", "<バンドルID>"]` を書きます。URL はアプリへ「URLを開く」Apple Event（`kAEGetURL`）として届くので、アプリは `applicationWillFinishLaunching` の中で `NSAppleEventManager` にハンドラを登録して受け取ります。起動していないとき・起動中のどちらでも届き、起動中なら同じプロセスに届きます。`kobito` スキームを Info.plist に登録する必要はなく、登録しません（ほかのアプリ宛ての URL まで受け取ってしまうため）。（2026-10-15、macOS 26.5 で確認）
- `open -b` は、バンドルIDが Launch Services に登録されていないと終了コード 1 で失敗します。開く側はこれを「宛先が起動できない」として扱います。

### 受け渡しの口（`receive`）

```json
"receive": [
  { "id": "new", "label": "新しいメモにする", "label_en": "New memo", "accepts": ["text", "image"], "url": "kobito://sample/import?mode=new&file={file}" },
  { "id": "append", "label": "開いているメモに足す", "label_en": "Append to open memo", "accepts": ["text", "image"], "url": "kobito://sample/import?mode=append&file={file}" }
]
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | そのアプリの中で一意な名前 |
| `label` | ○ | 送る側の画面に出す名前（日本語）。`label_en` は英語（任意） |
| `accepts` | ○ | 受け取れる中身（`text`・`image`・`file` の組み合わせ） |
| `url` | ○ | ② の形の URL。`{file}` を受け渡しファイルのパス（URL エンコード済み）に置き換えて開く |

送る側は、すべての起動情報の `receive` を集めて「送り先」の一覧を作ります。送り先のアプリ名は、起動情報の `name` を使います。

### 見せ方と操作

2026-10-20 に足した任意の項目です。アプリは、workspace とランチャーに見せる自分の姿と、外から呼んでよい操作を名乗れます。どれも任意です。無ければ、読む側は今までどおりに表示します（名前の1文字目のアイコン、色なし、種類名はそのまま、カードの日付はすべて予定の日として扱う）。考え方と画面での使い方は [APP_INTERFACE.md](APP_INTERFACE.md) にあります。

```json
"name_en": "Sample",
"icon": { "file": "/Users/…/Sample/kobito/icon.svg", "glyph": "✎" },
"color": "orange",
"kinds": [
  { "kind": "メモ", "label_en": "Memo", "glyph": "✎", "dates": "record" }
],
"actions": [
  { "id": "new", "label": "新しいメモ", "label_en": "New memo", "url": "kobito://sample/new", "role": "new", "shortcut": "cmd+n" },
  { "id": "diary-today", "label": "今日の日記", "url": "kobito://sample/diary/{today}" }
]
```

| 項目 | 内容 |
|---|---|
| `name_en` | 英語の表示名。無ければ `name` を使う |
| `icon` | アイコン。`file`（画像の絶対パス。`.svg` か `.png`、256 KB まで、正方形）と `glyph`（画像が無い・読めないときに出す1〜2文字。絵文字でもよい）。どちらも任意 |
| `color` | アプリの色。シリーズの配色の名前 `blue`・`green`・`orange`・`red`・`purple`・`teal`・`pink`・`gray` のどれか。知らない名前なら色を付けない |
| `kinds` | このアプリのカード（③）の種類ごとの見せ方の配列（下の表）。**配列の順が並べる順** |
| `actions` | 外から呼んでよい操作の配列（下の表） |

`kinds` の1件：

| 項目 | 必須 | 内容 |
|---|---|---|
| `kind` | ○ | カードの `kind` と同じ文字列。読む側は文字列として突き合わせるだけ |
| `label_en` | | 英語の種類名 |
| `glyph` | | バッジに添える1〜2文字 |
| `dates` | | カードの `date`・`start` の意味。`"event"`（予定の日時）・`"record"`（記録した日時：書いた日・登録した日）・`"none"`（カレンダーにも「今日」にも出さない）。無い・知らない値なら `"event"` |

- `due`（期限）と `done` は、`dates` によらず今までどおりに扱います。
- 名乗っていない種類は、名乗った種類の後ろに文字の順で並べ、`"event"` として扱います。

`actions` の1件：

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | そのアプリの中で一意で、変えない名前。ランチャーはこれで覚える |
| `label` | ○ | 表示名（日本語）。動詞で終える（「新しいメモ」「Todo を足す」） |
| `url` | ○ | ② の形の URL。宛先は**自分のアプリID**だけ。使える置き換えは `{today}`（開く側の PC の今日の日付 `YYYY-MM-DD`）だけ |
| `label_en` | | 英語の表示名 |
| `role` | | よく使う操作の決まった名前：`new`（新しいものを作る）・`settings`（そのアプリの設定画面を開く）。知らない `role` は、ふつうの操作として扱う |
| `shortcut` | | 埋め込み中にこの操作を呼ぶキー（⑤ `shortcut` の `key` と同じ形、`"cmd+n"` など）。案内に出すだけで、キーの処理は今までどおりアプリが行う |

- 開く側は、`{today}` を置き換えたあとの URL を ② と同じように開きます（workspace の中に表示できるアプリなら `navigate`、そうでなければ `command` の後ろに足して起動）。URL を自分で組み立てません。
- 宛先がほかのアプリID・`{today}` 以外の `{…}` を含む・`id` が重なる操作は、その1件を捨てます。
- ランチャーが操作を覚えるときは、アプリIDと操作の `id` だけを保存し、押されたときに起動情報を読み直して URL を得ます。
- 画像ファイル・色・種類・操作のどれかの形が違えば、その項目（配列ならその1件）だけを捨てます。

### workspace の中で表示するときの起動

`embed` を持つアプリを workspace の中で表示するとき、workspace は次の引数を足して起動します。

```text
<command> <embed> --dataset <基準パス> --parent-origin http://127.0.0.1:<workspaceのポート>
```

workspace は自分の画面を必ず `http://127.0.0.1:<ポート>` で開き、`--parent-origin` もこの形にします。`localhost` は使いません。`localhost` と `127.0.0.1` は別のサイトとして扱われるため、アプリの Cookie（SameSite=Strict）が iframe の中で送られず、アプリの API がすべて断られます。（2026-10-15、macOS の pywebview 6.2 で確認）

アプリは起動したら、自分の画面のURLを1行のJSONで標準出力に書きます：`{"kobito":"ready","url":"http://127.0.0.1:<ポート>/…"}`。workspace はそのURLを iframe で表示します。workspace はアプリの標準入力をつないだまま起動します。アプリは標準入力が閉じたら（workspace が落ちた場合も含めて）終わります。workspace が終わるときは、起動したアプリのプロセスも終了させます。基準パスを切り替えるときは、アプリを終了させてから新しい `--dataset` で起動し直します。

## ⑤ 埋め込みメッセージ

workspace の中の iframe では、pywebview の機能（`js_api`、ファイルのドロップで実パスを受け取ること、OS のダイアログ、メニュー）が使えません。そこで、それらは workspace に頼みます。やり取りは `window.parent.postMessage` と `message` イベントで行い、宛先と送り元の origin を必ず確かめます。

```json
{ "kobito": 1, "type": "pick", "id": "req-1", "kind": "folder", "directory": "/Users/…" }
```

| `type` | 向き | 内容 |
|---|---|---|
| `ready` | アプリ → workspace | 画面の準備ができた。`title`（任意）を付けられる |
| `title` | アプリ → workspace | 表示中の見出しが変わった（`title`） |
| `open` | アプリ → workspace | ② のリンクを開いてほしい（`url`） |
| `pick` | アプリ → workspace | OS のダイアログでファイル・フォルダを選んでほしい（`id`、`kind`：`file`／`files`／`folder`、`directory`（任意）） |
| `picked` | workspace → アプリ | `pick` の答え（`id`、`paths`：選ばれなければ空の配列） |
| `drag` | アプリ → workspace | 画面の上にファイルがドラッグされてきた。workspace はファイルを受け取る透明な層を iframe の上に重ねる |
| `dropped` | workspace → アプリ | 落とされたファイルの実パス（`paths`、iframe の中の座標 `x`・`y`） |
| `shortcut` | workspace → アプリ | workspace のメニューで、アプリ向けのショートカットが押された（`key`：`"cmd+n"` など） |
| `notify` | アプリ → workspace | 通知を出してほしい（`title`、`body`） |
| `navigate` | workspace → アプリ | このアプリ宛ての ② のリンクを開いてほしい（`url`）。workspace は、宛先のアプリが iframe で表示中なら起動情報で別に起動せず、これを送る |

- `kobito` は版番号で `1` のままにします。読む側は、知らない `type` を無視します。
- 単体で起動しているときは、アプリは自分の pywebview の機能を使い、このメッセージは使いません。

## ⑥ 基準パスの履歴

このPCで kobito シリーズのアプリが開いた基準パスの一覧です。各アプリは、保存先を選ぶ画面の候補としてこれを使います。

```json
{ "v": 1, "datasets": [ { "path": "/Users/…/Google Drive/My Drive/kobito", "id": "my-data", "app": "sample", "opened": "2026-10-15T09:00:00+09:00" } ] }
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `path` | ○ | 基準パスの絶対パス |
| `id` | ○ | `dataset.json` のID |
| `app` | ○ | 最後に開いたアプリのID |
| `opened` | ○ | 最後に開いた日時 |

- 置き場所は macOS で `~/Library/Application Support/kobito-tools/datasets.json`、Windows で `%APPDATA%\kobito-tools\datasets.json` です。
- 書くときは、読み直して自分の1件を足すか更新し、一時ファイルから置き換えます。`path` が同じ項目は1件にまとめます。
- 読む側は、`path` に `.kobito-tools/dataset.json` が今もあるかを確かめてから候補にします。

## ⑦ 受け渡しファイル

あるアプリの中身（文字・画像・ファイル）を、別のアプリへ渡すときの形です。送り先は、④ の `receive` から選びます。

```json
{ "kobito": 1, "type": "share", "from": "other", "created": "2026-10-15T09:00:00+09:00",
  "text": "…", "images": [ { "name": "クリップ1.png", "mimeType": "image/png", "base64": "…" } ],
  "files": [ { "path": "/Users/…/x.pdf", "name": "x.pdf" } ] }
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `kobito`・`type` | ○ | `1`・`"share"` |
| `from` | ○ | 送ったアプリのID |
| `created` | ○ | 作った日時 |
| `text` | | 文字 |
| `images` | | 画像（名前・MIME タイプ・base64） |
| `files` | | ファイルの絶対パスと名前（中身は入れない） |

- 送る側は、OS の一時フォルダの `kobito-share/`（権限 700）に `<UUID>.json`（権限 600）として書き、`receive` の `url` を開きます。
- 受け取る側は、`kobito-share/` の中のファイルだけを読み、読み終えたら消します。それ以外の場所のファイルは読まずに断ります。
- 24 時間より古いファイルは、送る側・受け取る側のどちらが消してもかまいません。
